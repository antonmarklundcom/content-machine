## The one-line diagnosis

**Four phases (O1, O2, S3, O3) shipped code that has never run against a
database or the Gemini API.** Every phase log says "code complete,
UNVERIFIED" for the same reason: build sessions have no `DATABASE_URL` and no
`GEMINI_API_KEY`, and the app's Neon-HTTP driver cannot talk to a local
Postgres. The code quality is high (the schema comments, the spend cap, the
usage mapping are all careful), but nobody knows whether `/api/generate`,
promote, clips or the batch pipeline work. Everything else in this review is
secondary to making the app verifiable by a build session.

## Findings, ranked

### A. Verification and delivery (blocks everything else)

1. **No path to a database from a build session.** `src/db/index.ts` is hard-
   wired to `@neondatabase/serverless`'s HTTP driver. A local `postgresql-16`
   is available in the cloud sessions and cannot be used. S3 correctly refused
   to change this as a Sonnet phase; it is an Opus foundation change.
2. **No integration tests, no route tests.** 192 tests, all pure functions.
   The spend cap's SQL, the clips upsert, the promote insert, the poller's
   batch state machine: untested as executed code.
3. **No CI.** `.github/` does not exist. Old plan §1.2 says "Actions is CI
   only (typecheck/build on push)" — that CI was never created. A PR can merge
   red.
4. **Migrations are a recurring human step.** §7 item 1 ("run
   `db:migrate && db:seed`") has been open since O1. Nothing applies migrations
   on deploy.
5. **The S4 gate asks for something impossible.** "Run
   `npm run yt:probe-captions` from the deployed env" — Vercel has no shell.
   The probe exists only as a CLI, so the verdict that gates S4 can never be
   produced from the production IP.
6. **No lint.** No ESLint, no Prettier. `next build` is the only style gate.

### B. Production correctness on Vercel

7. **No cron is scheduled.** `/api/cron/poll`'s comment still says "the
   endpoint Hostinger's cron calls hourly". Home is Vercel (§1.1); there is no
   `vercel.json` with a `crons` entry. The poller never runs in production.
8. **The poll's re-entrancy lock is a module variable.** `let running = false`
   is per-instance; on serverless two concurrent invocations land on two
   instances and both run. The comment even names the harm (double-submitted
   batch, wasted quota). Needs a DB lease.
9. **`/api/cron/poll` sets no `maxDuration`.** A poll that ingests 10 sources
   and submits a batch will exceed Vercel's default function timeout.
10. **`/api/generate` spends money without an owner check.** `roles.ts`
    states "the permission boundary is spend"; `analyze.actions.ts` and
    promote's `adapt` honour it; `/api/generate` (the most expensive call in
    the app, ~$0.11+) is open to any signed-in user.
11. **Clips can stick in `ingesting` forever** (KNOWN-ISSUES O2). One dead
    request = one row nothing clears. A reaper is ~15 lines inside the poll
    run.
12. **`researchNoteId: insertedNoteIds[0]`** links every idea of a run to the
    first research note whether or not it relates. Cosmetic today, wrong data
    tomorrow.
13. **`/api/generate` loads every `research_notes` row** and filters in JS.
    Fine at 50 rows; a `jsonb` containment query is the right shape.

### C. Product and UI

14. **Two design systems.** `/` and `/brand/[id]` use the original hand-
    written CSS (`@layer legacy`, inline `style={{}}` in `BrandIdeas.tsx`,
    English-only, `fetch` in a client component, no spend meter). `/youtube/*`
    and `/inbox` use the Tailwind token system, i18n, `Header` with
    `SpendMeter`. The scoping hack `:not([data-youtube-section] *)` on every
    bare-element selector exists only to keep the two from fighting.
15. **The ideation loop ends at "approve".** No copy-to-clipboard for a
    caption (the YouTube half already has `CopyTextButton`), no "posted"
    state, no way to see what a run cost, no filter by status, no delete of
    rejected ideas. The product's deliverable is the caption and there is no
    ergonomic way to take it out of the app.
16. **README describes half the app.** No mention of login, `/youtube`,
    `/inbox`, capture, spend cap, or the plan/prompts workflow.
17. **`dictionary.ts` is one 658-line file.** Any two parallel phases that add
    UI copy collide in it. Needs splitting per feature before lane 2 runs.

### D. Money math (already handled well; two notes)

18. Rates dated 2026-08-29; 3.7 Flash priced at standard rate until the intro
    rate lapses 2026-12-31 (deliberate over-report). No action; recorded.
19. Grounding has no `max_uses`; the reservation can under-hold. Re-baseline
    after the first real runs (the smoke script in O5 prints the figures).

## Decisions (Fable, 2026-09-11) — all recorded as PLAN.md §1 items 12–24

- **Verifiability is the foundation phase.** Driver switch (Neon HTTP in
  production, `pg` everywhere else), CI with a Postgres service container,
  integration tests, a Gemini test double, and one live smoke script. No
  feature work until the four unverified phases have been exercised.
- **Migrations run on deploy.** `vercel-build` = migrate + seed + build. The
  human step in old §7.1 disappears permanently.
- **Vercel Cron is the scheduler**, declared in `vercel.json`. Vercel sends
  `Authorization: Bearer $CRON_SECRET`, which `cron-auth.ts` already accepts.
- **DB lease replaces the module-level lock.**
- **Spend is owner-only everywhere**, `/api/generate` included.
- **One design system: the Tailwind token system + i18n.** The legacy CSS
  layer is deleted. Not a redesign; a port of two pages onto the existing
  system.
- **Ideas get `posted` status + `postedAt`**, copy button, status filter,
  per-run cost. Still no scheduling or posting integration (README promise
  stands).
- **The caption probe becomes an owner-only route** so the verdict can be
  produced from the production IP. S4 (IG/FB metadata, Hostinger worker)
  stays in the backlog until that verdict exists.
- **ESLint + Prettier are adopted**, in the link pass (sequential), because a
  repo-wide autofix collides with every parallel phase.
- **Build process follows the current `phased-autonomous-build` method**:
  per-phase `docs/log/<phase>.md` instead of a growing §9; screenshots in CI
  artifacts, never git; a Sonnet watcher Routine instead of any live
  supervision; Opus lane first, then all Sonnet phases in parallel.
- **Secrets for verification**: recommended in §7 that Anton adds a Neon
  *dev-branch* `DATABASE_URL` and a capped `GEMINI_API_KEY` to the Claude
  Code cloud environment so O5 can run the live smoke itself. If he prefers
  not to, the smoke script is a one-command local run for him.

## Rejected / parked

- Provider abstraction behind `ai.ts` — one module already; abstraction
  without a second provider is cost.
- Merging `research_notes` into `topics`/`entities` — old §8, still a
  refactor with no user asking for it.
- Audio transcription for IG/FB — old §1.8, still ~20x.
- Structured logging/observability — Vercel's function logs are enough at
  this volume.
- Telegram capture — backlog.
