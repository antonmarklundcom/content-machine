# S13 — Brands, families, accounts, kits

## Built

- `/brands`: every brand (active or not) with family and account count; owner-only "New brand" form.
- `/brands/[id]`: accounts list (status select, inline edit, add), brand edit form, links to
  `/brand/[id]` (ideas, unchanged) and the kit.
- `/families`: families with their brands, inline rename/notes, owner-only create.
- `/accounts`: every account across brands, filterable by platform and status.
- `/brand/[id]/kit`: kit editor — colour rows with live swatches and hex validation, fonts,
  logo picked from the media library (brand + unsorted images, thumbnail preview), Higgsfield
  element/character ids + style notes, CTAs, hashtags, dos/don'ts.
- `src/lib/accounts.actions.ts`: `saveBrandAction`, `saveFamilyAction`, `saveAccountAction`,
  `setAccountStatusAction`, `saveKitAction` — owner-only, `{ ok } | { ok: false, error }`.
- Components `Account{Fields,Form,Row,StatusSelect}`, `Family{Form,Card}`, `KitEditor`;
  `dict/accounts.ts` en + sv.
- `tests/integration/accounts-ui.test.ts` (5): brand + family + account + kit created, refusals.

## Decisions

- Brand and family ids are slugs, read-only after create; `mode=edit` never changes the id.
- Account handles are stored without `@`; platform + handle clashes name the owning brand.
- Hex is normalised to lower-case `#rrggbb` (`#abc` expands); anything else is refused, not guessed.
- Hashtags stored without `#` (matches O11's `captionText`); lists dedupe and keep order.
- Logo must be an image asset of this brand or an unsorted one; rejected/archived are not offered.
- Writes go straight to `db` in the actions file: the bridge is read-only for these tables and
  lane 2 may not extend it (§4.7). §10: move brand/family/account/kit writes into the bridge.
