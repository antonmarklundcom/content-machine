# O5 — Gemini test double + live smoke

## Built

- `src/lib/ai-fake.ts`: `models.generateContent`, `generateContentStream`,
  `batches.create/get`. Classifies each request from the `responseJsonSchema`
  it carries, and validates its canned answer against that same schema on every
  call (a ~50-line JSON-Schema subset, no new dependency) — an unrecognised
  schema throws rather than answering.
- Usage figures chosen to exercise the money math, not skip it: the analysis
  call carries a cached prefix (proves `readUsage` subtracts it), the ideation
  call carries reasoning tokens (proves they bill as output), grounded calls
  report 3 `webSearchQueries` split across chunks (proves the union in
  `generateContentPlan`). Every call is recorded in `fake.calls`.
- Interactive responses are real `GenerateContentResponse` instances; batch
  `inlinedResponses` are JSON-round-tripped, so each path exercises the half of
  `responseText` that actually runs there.
- `src/lib/ai.ts`: one branch in `geminiClient()`, ahead of the cache. No other
  change — no live run happened, so no estimate was re-baselined.
- **41 new integration tests** (75 total): `generate` (9), `promote-adapt` (8),
  `clips-analyze` (9), `poll-batch` (10), `outline` (5), plus 7 unit tests on
  the fake's own guarantees (206 unit total).
- `tests/integration/route.ts`: runs App Router handlers directly, with a real
  signed session cookie. `tests/integration/preload.mjs` makes that possible.
- `scripts/smoke.ts` + `npm run smoke`: refuses under `GEMINI_FAKE`, `--dry-run`
  prints the plan and every reservation, live run prints raw `usageMetadata`,
  query counts, cost, reservation-vs-actual per step, and a re-baselining block.

## Decisions

- **Requests are classified by their schema's property names**, not by importing
  the five schema constants: `IDEAS_JSON_SCHEMA` and `ADAPT_JSON_SCHEMA` are
  private to `ai.ts`, and importing the other three would point the fake back at
  half the app. `ai-fake.test.ts` closes the gap by validating each payload
  against the three real exported schemas.
- **The fake is cast once, at the seam.** `GoogleGenAI` has private fields, so no
  structural stand-in can satisfy it; `FakeGemini` pins its own methods to the
  SDK's parameter and return types instead, and `geminiClient()` casts once.
- **The seam sits ahead of `cachedClient`** and re-reads the env every call, so a
  cached fake can never outlive the flag — the failure that direction is a live
  run silently answering from canned data.
- **`tests/integration/preload.mjs`, loaded with `--import`**, does two things a
  test module cannot do late enough for itself: puts `AsyncLocalStorage` on
  `globalThis` (Next's request-scope modules throw at import without it) and
  replaces `next/navigation`, which cannot load under `--conditions=react-server`
  at all because React's react-server build has no `createContext`. A flag
  rather than a must-be-first import, because S9's repo-wide autofix reorders
  imports.
- **The smoke script wraps the SDK client from outside** to record usage, rather
  than adding a second hook to `ai.ts`. A diagnostic should not sit in the path
  of every production call, and wrapping means it measures exactly the traffic
  production sends.
- **The smoke run needs `--conditions=react-server` too** (`server-only`), same
  as `test:db`; it is in the npm script.

## Known issues

- **The live smoke has not been run.** No `DATABASE_URL` or `GEMINI_API_KEY` in
  this environment (§7.1 item 1 still ☐), so per §5.O5.4 the exact command is in
  `docs/decisions-needed.md` and the three reservation constants in `ai.ts` are
  still unmeasured guesses. Everything else about the paid paths is in CI.
- **`tests/integration/route.ts` imports two Next internals**
  (`work-async-storage.external`, `work-unit-async-storage.external`). A Next
  upgrade could move them. The failure is loud and localised — the import fails,
  every route test fails at once, one file to fix — which beat booting a real
  server per test or leaving the handlers as the untested half.
- The prompt file asked for the `claude-api` skill before touching `ai.ts`. That
  skill's own SKIP rule fires here (it names Gemini explicitly, and the mandated
  `grep` hits `@google/genai` across the repo), and the model-cost guardrail it
  was cited for actually lives in `fable-cost-guardrail` and PLAN §4.8, which
  were followed. Worth correcting in `prompts/opus-6-prod-hardening.md` if it
  carries the same line.
- `/api/clips` reaches `analyzed` in tests with the YouTube Data API stubbed at
  `fetch` and the transcript pre-seeded, so the caption pipeline returns
  `already-have-transcript`. Captions themselves are still unverified against a
  real host — S7 was dropped (§1.28); the first real run is from Anton's PC.
- The batch path is only exercised with inlined requests. `collectBatchResults`
  throws a named error for a file-backed result and the fake never produces one;
  a much larger backfill would need that path (already in KNOWN-ISSUES.md).
