# O6 — Production hardening (local-first)

## Built

- `leases` table + `src/lib/lease.ts`: one-statement acquire (`INSERT … ON CONFLICT
  (name) DO UPDATE … WHERE leases.expires_at < now() RETURNING`), holder-keyed
  release, `withLease(name, ttlMs, fn)` releasing in `finally`. TTL 30 min for `poll`.
- `/api/cron/poll` and `npm run yt:poll` both take the `poll` lease; the route answers
  409, the CLI prints "already running" and exits 0. Module-level `running` flag gone.
- `/api/generate`: signed out → 401, not owner → 403, both `{ error }` like promote's `adapt`.
- Clip reaper in `pollSources`, before sources: `ingesting` + `saved_at` > 15 min →
  `failed`, "Ingest timed out — retry". `PollResult.reapedClips`, in the route summary.
- Research notes: loaded with `related_brand_ids::jsonb @> '["<brand>"]'`; ideas link to
  the first returned note the model tagged with this brand, else `null`.
- `posted` in `IDEA_STATUSES`, `ideas.posted_at`; PATCH stamps it entering `posted`, keeps
  it on a repeat, clears it leaving — one UPDATE with a `CASE`, no read-then-write.
- Migration `0004_productive_hawkeye.sql`: `leases` + `posted_at`.
- i18n split into `src/lib/i18n/dict/{app,nav,spend,youtube,video,inbox,promote}.ts`, plus
  empty `brands`, `ideas`, `admin` already spread in `dictionary.ts`. 270 keys, values
  byte-identical (checked before/after); `keys.snapshot.json` + test pin it.
- 13 new integration tests (88 total): `lease` (6), `ideas-posted` (3), `generate` (+4).

## Decisions

- **Time math in SQL only** (lease expiry, reaper cutoff): the PC and a deployed route
  may disagree about the clock; the database's `now()` is the one they share.
- **The key snapshot pins the split files, not the whole dictionary**, so lane 2 adds keys
  to its own file without touching the snapshot (which would be outside its Owns).
- **`related_brand_ids` stays `json`** and is cast to `jsonb` in the query — a type change
  migration for one containment query was not worth it at this table size.
- **Cron route otherwise unchanged** (§1.27): no `maxDuration`, no `vercel.json`.

## Known issues

- The reaper keys on `saved_at` (as specified). A clip saved > 15 min ago and *retried*
  has an old `saved_at`, so a poll during that retry fails it early. It self-heals when
  ingest finishes (the save path writes the final status), but the right key is a
  `status_changed_at` column set in `src/lib/clips/save.ts` — not in O6's Owns.
- `/api/generate` is owner-only now, but the brand page still shows Generate to employees
  (they see the 403 message). Hiding it is S5/S6's (`src/app/brand/**`).
- Handoff audit: `yt:poll --wait` could outlive the 30-min lease (awaitBatch alone waits
  30 min); `--wait` runs now take a 2 h TTL. Fixed in the follow-up PR.
- The CLI test spawns `tsx` in a child process (~2 s); the only way to prove the script,
  not just the library, honours the lease.

### Windows Task Scheduler entry (for S8 to copy into docs/LOCAL-SETUP.md)

Run once in an elevated `cmd`, with the repo path adjusted; `.env` is read from the
working directory, so the `cd /d` matters:

    schtasks /Create /F /SC HOURLY /MO 1 /TN "content-engine yt-poll" ^
      /TR "cmd /c cd /d C:\dev\content-engine && npm run yt:poll >> poll.log 2>&1"

Exit codes: 0 ok or already running, 3 spend cap hit, 1 crashed.
