# O4 — Verification foundation

## Built

- `src/db/driver.ts`: one pure `resolveDriver(url, override)` — `*.neon.tech`
  (or `DB_DRIVER=neon`) picks Neon HTTP, anything else picks `pg`. 7 unit tests.
- `src/db/index.ts` and `migrate.ts` both follow it; `pg` + `@types/pg` added.
  `closeDb()` is now real for the pool (it was a no-op shim).
- `drizzle.config.ts` calls `resolveDriver` as a URL guard only — see Decisions.
- `tests/integration/setup.ts`: migrates once per process, truncates every
  `public` table between files, refuses to run against a Neon URL at all.
- **34 integration tests** against real Postgres, in four files: `spend` (10),
  `clips` (11), `seed` + brand bridge reads (8), `promote` (5).
- `.github/workflows/ci.yml`: Node 22 + `postgres:16` service → typecheck,
  unit tests, migrate, `test:db`, build. Plus a `screenshots` job scaffold.
- `tests/screenshots.mjs`: Playwright, 2 widths, uploads the git-ignored
  `docs/screenshots/` as a CI artifact. One page until S5 fills the list.
- Scripts: `test:db`, `verify`, `vercel-build`. `.env.example` + one README
  paragraph on running against a local Postgres.

## Decisions

- **`db` stays typed as `NeonHttpDatabase`**, with the `pg` handle cast to it.
  §1.13 requires the exported surface to be unchanged, and `src/lib/tags.ts`
  derives its `Tx` type from `typeof db.transaction`; a union would have forced
  edits into files this phase does not own. The one real divergence is logged below.
- **No `driver` key in `drizzle.config.ts`.** Unlike the app, drizzle-kit has
  nothing to switch: a Neon endpoint serves TCP on the same hostname it serves
  HTTP, so its one client reaches both. `resolveDriver` is called there purely
  to reject a malformed `DATABASE_URL` early.
- **`test:db` needs two flags**, both in the script: `--conditions=react-server`
  so the `server-only` marker in `promote.ts`/`bridge/`/`clips/save.ts` resolves
  to its empty build instead of throwing, and `--test-concurrency=1` so one
  file's truncate cannot land inside another file's assertions.
- **Playwright is installed `--no-save` in CI**, not as a devDependency: ~400MB
  that only the screenshots job wants. `PLAYWRIGHT_CHROMIUM_PATH` reuses an
  already-installed browser locally.
- Migrations are applied by `setup.ts` as well as by the CI step, so
  `npm run verify` finds a schema without a separate migrate.

## Known issues

- **`db.transaction()` throws on Neon and works locally.** `neon-http`'s session
  raises "No transactions support in neon-http driver"; `node-postgres` runs it.
  Two call sites use it — `src/lib/video.actions.ts:57` and `src/lib/tags.ts:61`
  — so **both are broken in production today and a green `test:db` does not say
  otherwise**: the pg driver these tests use is the one that supports them. This
  predates O4 and neither file is in this phase's Owns column. Recorded in
  `docs/decisions-needed.md`; the fix is either `drizzle-orm/neon-serverless`
  (WebSocket Pool, supports transactions) for production, or rewriting those two
  call sites as single statements. Worth settling before S6 adds ideas writes.
- `canonicalClipUrl` does not strip the `utm_*` family — the allowlist has
  `source`/`ref`/`si`/`feature` but not `utm_source`, which is the most common
  share marker there is. So the same video shared from two apps can become two
  clips. Deliberate direction (a duplicate row beats a collision overwriting
  someone's note) but a cheap win for whichever phase next owns `clips/url.ts`.
  A test pins the current behaviour so a change is a visible decision.
- **An all-digit env value in a workflow is a number, not a string.** The first
  CI run set `SESSION_SECRET` to 64 unquoted zeros; YAML read that as the
  integer `0`, the app got a one-character secret, and every authenticated page
  500'd. `next build` passed anyway — these pages are server-rendered on demand,
  so a build never evaluates the secret — and only the screenshots job caught
  it, which is a fair argument for keeping that job. The value is quoted and has
  letters in it now. Worth remembering when S5 adds pages or O6 adds env.
- Nothing here touches Gemini or a real API key. `src/lib/ai.ts` is still
  entirely unverified; that is O5's whole job.
