# S6 — Ideas workflow

## Built

- `src/lib/bridge/ideas.ts`: `listIdeas({brandId, status?, page?})` (30/page, id tiebreak),
  `listAllIdeas`, `ideaCountsByStatus` (zeros included), `getIdea`, `updateIdea`
  (the §1.23 `posted_at` CASE rule, now in one place), `deleteRejectedIdea` (one
  `DELETE … WHERE status='rejected'`), `isIdeaStatus`. Exported from `bridge/index.ts`.
- `PATCH /api/ideas/[id]` now calls `updateIdea`; `GET /api/ideas` takes `?status=` and
  `?page=`, still returns a bare array, unpaged without `?page` (BrandIdeas relies on it).
- `src/lib/ideas.actions.ts`: `setIdeaStatus` + `saveIdeaEdits` (any signed-in user),
  `deleteIdea` (`requireOwner`, rejected only). All revalidate `/brand/<id>`.
- Components: `IdeaStatusTabs` (server, `?status=` links with counts), `IdeaActions`
  (client: status moves, copy caption via `CopyTextButton`, owner delete on rejected,
  posted date), `IdeaCitations` (http(s) sources as links), `IdeaVisualNotes` (`<details>`).
- `dict/ideas.ts`: 18 keys, en + sv. `tests/integration/ideas.test.ts`: 6 tests.

## Decisions

- **Not mounted** on `/brand/[id]` — S5 owns `src/app/brand/**`; S5/S9 mount the exports.
- **Actions throw plain `Error`s** (a `"use server"` file exports only async functions);
  the UI shows one generic i18n failure line, since production strips action messages.
- **Delete is one conditional statement**, so an idea re-approved between check and
  delete is never removed; `getIdea` first only picks the error message.

## Known issues

- The action tests stub `incrementalCache` on the work store themselves: `callRoute`
  (`tests/integration/route.ts`, not in S6's Owns) does not set it, and `revalidatePath`
  needs it. S9 could move the stub into `callRoute` for future action tests.
- `saveIdeaEdits` has no S6 component; S5's idea card is expected to call it.
