# S17 — Clip fetch + transcript

## Built

- `src/lib/clips/fetch/`: `binaries.ts` (yt-dlp/ffmpeg from `YTDLP_PATH`/`FFMPEG_PATH` or PATH,
  detected once), `ytdlp.ts` (`--no-playlist`, `--max-filesize` 200 MB + post-check, timeout,
  optional `YTDLP_COOKIES_FILE`, caption from the info json), `telegram.ts` (Bot API `getFile`,
  20 MB), `shrink.ts` (ffmpeg re-encode past the 14 MB inline limit), `index.ts` (`fetchClip`,
  `eligibleClipIds`, `fetchEligibleClips`).
- Flow: download into `captures/<clip-id>/` → O10 `registerFile` (source `capture`/`telegram`,
  tags `research` + purpose) → O11 `transcribeClip` → transcript/postText/summary/claims/fetchedAt.
- `scripts/clips-fetch.ts` (`--limit`, `--id`, `--retry-failed`): only `fact_check`/`competitor`.
- `/clips/[id]`: player (O10's owner-only asset route), summary, claims ("Save claim as fact"),
  "Save hook", on-screen text, transcript, "Fetch + transcribe" (owner). `ClipMedia{Player,Actions}`.
- `src/lib/clip-fetch.actions.ts`; `src/lib/i18n/dict/clipFetch.ts` (+ its lines in `dictionary.ts`).
- `tests/integration/clip-fetch.test.ts` (7) with `tests/fixtures/fake-yt-dlp.mjs` + Gemini fake.

## Decisions

- Fetch never touches `clips.status` (YouTube pipeline's); failure sets `clips.error` only.
- Failed clips are skipped by the batch job until a click or `--retry-failed` (retry is §10).
- A click fetches any purpose, `inspo` included (§1.44 "or when the owner clicks").
- Re-run reuses the registered media if still on the drive; the batch stops at a missing drive or the cap.
- Claims saved as facts are `verified=false` (cleared in the action after `createFact`), source = clip URL.
- Without ffmpeg yt-dlp takes a single-file format (`b[ext=mp4]/b`); shrunk copy is `.media.small.mp4` (scan skips dot-names).
