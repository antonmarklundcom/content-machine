# S14 — Media library + Higgsfield commands

## Built

- `/media` (library) and `/media/inbox` (unsorted = no brand): one server view `MediaLibrary`,
  GET-form filters (brand/unsorted, account, status, source, kind, tag, from/to inclusive) in
  `src/app/media/query.ts`, 60-per-page grid of O10 thumbnails only, pagination, tab counts.
- Detail drawer from `?asset=<id>` (prompt, model, source link, tags, file, size, "used in" via
  `listAssetUses`); the full file loads only there. "Media drive not connected" banner.
- `src/lib/media.actions.ts`: `bulkMediaAction` (tag/untag/assign/approve/reject/archive/restore,
  ≤ 200 ids, every field validated) and `scanNowAction` (O10 `scanMediaRoot`).
- Assigning a brand to an `_inbox/` file moves it via `localDriver` to
  `<brand>/<handle|_brand>/<YYYY-MM>/<file>` and repoints the inbox `manifest.json` entry.
- `.claude/commands/higgsfield-post.md`, `higgsfield-import.md`; `docs/HIGGSFIELD.md` updated.
- `media.ts` dict (en + sv); `tests/integration/media-ui.test.ts` (8 tests).

## Decisions

- An asset with no post goes to `<brand>/<handle|_brand>/<YYYY-MM>/<slug>.<ext>` (month of
  `created_at`); a taken name gets `-<asset id>`. Only files under `_inbox/` move on assign.
- Unassign (brand → none) changes the row only; the file stays where it is.
- All bulk ops and Scan are signed-in (editorial, no spend); media bytes stay owner-only (O10).
- Row writes live in the action (bridge is reads-only by its README); bytes via O10 modules only.
- `/higgsfield-import` spends nothing, so it skips `models_explore`; `/higgsfield-post` always
  recommends first, batches, `jobs_wait`s and resumes from the post folder's manifest.
