## Unverified risks and configuration gaps

- **CM-RISK-01 — actual Hostinger environment:** plan entitlement, Node/npm install/build versions, MariaDB version, connection access, memory/process limits and persistent media capacity still require hPanel verification. CI is compatibility evidence, not a deployed-host proof.
- **CM-RISK-02 — hybrid media visibility:** a local PC path is not readable from the hosted server. The owner must choose hosted persistent uploads/public delivery or an explicit PC handoff; ffmpeg, CLI subscriptions and local cloning are not automatically available on managed Node.js.
- **CM-RISK-03 — real provider behavior:** OAuth scopes, callback URLs, account/channel ownership, token expiry, API rate limits and live upload/publishing responses were mocked. No live account/provider certification.
- **CM-RISK-04 — durable scheduling:** choose exactly one scheduler for each job. No schedules were installed or hosted worker/deployment binding created. In-process rendering still needs a restart-safe production runner if unattended rendering is required.
- **CM-RISK-05 — backup operation:** CI proves a synthetic SQL dump/restore. A production restore must also cover media, configuration and separately protected encryption keys; actual cadence/retention/access are unconfigured.
- **CM-RISK-06 — budget estimates:** unknown outcomes intentionally retain conservative estimates. Configured prices/ceilings and credit services require owner review; the ledger is not a guarantee that an external vendor cannot charge more than estimated. Human reconciliation is still required for uncertainty.
- **CM-RISK-07 — approval product policy:** editor approval protects recorded revisions/assets/account. Language/audience/kids classification and offer/legal claims still require a deliberate owner review policy; do not infer an unlimited approval guarantee.
- **CM-RISK-08 — coverage:** full native DB, unit and mock routes are exercised. Browser click-through with real account configuration, actual hosted filesystem persistence, paid provider interruptions, real remote publishing and disaster restoration of operational media remain separate pilot work. Windows file symlinks require privileges; normal directory junction paths are covered.
- **CM-RISK-09 — filesystem cooperation:** immutable staging/promotion protects app-controlled writes. An external process writing directly to final paths can defeat cooperating-lock fallback on filesystems without hard-link support. Reconcile abandoned staging only with all workers stopped.

No finding above claims that every bug has been found. Baseline historical reports, newly confirmed defects, remaining risks and owner configuration are deliberately distinguished.
