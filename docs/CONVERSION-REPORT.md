Verified on GitHub Actions: native MariaDB 10.11 and 11.4 clean installs, production dependency audit, root and worker typechecks, lint/format, 684 unit tests, 25 worker tests, 411 native integration tests per database version with ffmpeg available, native SQL dump AND restoration of 51 tables, production builds and physically isolated Linux standalone artifact checks including synthetic proxy headers/canonical login origin. Windows clean install, type/lint, production build and worker checks passed; 683 of 684 root unit tests passed with one documented POSIX fake-CLI executable test skipped on Windows; Windows CI file-symlink containment passed. No tests failed. The dated production npm audit found zero known advisories; nine development-tool dependency advisories remain separately assessed in the findings. Local checks also verified the installed caption library with zero network requests and migration metadata with drizzle-kit check. [Verified code CI run](https://github.com/antonmarklundcom/content-machine/actions/runs/37854603317) and the PR head checks are authoritative for the final merge revision.

Native CI uses guarded disposable `_test` databases and synthetic/provider fixtures. Clean install, type/lint, worker and full app tests are mandatory. Backup verification snapshots every table/schema, dumps with native mariadb-dump, drops only the guarded synthetic database's tables, restores using native mariadb, and compares restored schema/rows including Unicode/case identities and UTC milliseconds. The Linux artifact is physically copied outside the source tree, resolves mysql2 inside its own dependency tree, boots with no DATABASE_URL/provider credentials, serves real static output and refuses an unauthenticated private asset request.

That artifact check does not certify authenticated production data, live OAuth, hosted media persistence or live paid/publishing providers. Database-backed workflow tests use mocks. Actual browser editing with the owner's accounts/assets and production backup+media/key restore must be performed during a separately authorized pilot. No guarantee of zero remaining defects.

## Measurable finished v1

1. Clean checkout installs/builds with the documented runtime; a fresh target database migrates and seeds safely; startup opens no paid provider request. Required CI remains green.
2. One brand/offer/account can complete ten content packs through capture→evidence→brief→draft→known files→owner review. Employees prepare; only the owner authorizes spending/sending. Wrong-brand assets and stale revisions are refused.
3. Missing files, provider failure, disconnect/restart and partial output have visible recovery actions. Known remote IDs are reused; duplicate job/scheduler clicks do not create another paid request or public post. Unknown outcomes remain blocked for reconciliation.
4. Schedule timestamps display in the chosen local timezone and persist in UTC. One due runner handles the pilot; one separately approved live publication per enabled platform is confirmed manually before unattended work.
5. Actual DB, ten representative media assets and encryption-key configuration restore into isolation with matching records/hashes and a tested ≤24-hour recovery-point target. Private retention/access owner recorded.
6. Track baseline editing/production time for five packs, then aim for at least 30% less operator time over ten comparable packs with acceptable quality. This is an acceptance target, not a demonstrated savings claim.
7. For four weekly cycles, record offer/CTA, qualified leads and outcomes (manual is sufficient), accepted content cost and one keep/change/stop decision. Reach and generation counts alone cannot satisfy business completion.
