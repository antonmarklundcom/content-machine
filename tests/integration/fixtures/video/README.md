# YouTube and TikTok publishing fixtures (build 4 §3.F)

Hand-recorded response shapes, used by `tests/integration/b4-f-publish-video.test.ts` and the unit
tests in `src/lib/{google,tiktok,publish}/*.test.ts`.

- `youtube/`: Google's token endpoint (code exchange, refresh, `invalid_grant`), `channels.list?mine=true`,
  the `videos.insert` resource returned when a resumable upload completes, `thumbnails.set`, and
  error bodies (401 `authError`, 403 `quotaExceeded`, 503 `backendError`). The resumable session's
  `Location` header and the 308 `Range` answers are generated by the tests' fake `fetch`.
- `tiktok/`: the v2 token endpoint (flat answer, `invalid_grant`), `user/info`, `creator_info/query`,
  inbox and direct `video/init`, `status/fetch` (processing, inbox, complete with an int64 post id,
  failed) and error envelopes (`rate_limit_exceeded`, `access_token_invalid`).

Not captured live (PLAN-build4 §1.12): the shapes follow Google's and TikTok's API docs as known, so
the live paths are UNVERIFIED until the accounts are connected.
